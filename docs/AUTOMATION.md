# 자동화 운영 안내

Python 3.9 이상과 Git으로 동작하며, 모든 날짜와 마감은 한국 시간(`Asia/Seoul`) 기준입니다.

## 설정

- 기본 브랜치는 `main`입니다.
- **Settings → Secrets and variables → Actions**에 `DISCORD_WEBHOOK_URL`을 등록합니다.
- 워크플로에는 저장소 내용 쓰기 권한이 필요합니다. 브랜치 보호 규칙이 자동 커밋을 막지 않도록 확인해 주세요.
- 웹훅 주소는 코드에 적지 않습니다.

[`study_config.py`](../study_config.py)에서 다음 항목을 수정합니다.

- `MEMBERS`: 현재 참여자 명단. 이름을 폴더 이름으로 사용합니다.
- `MEMBER_EMOJIS`: 이름별 이모지. 지정하지 않은 사람은 `DEFAULT_MEMBER_EMOJI`(`🐾`)를 사용합니다.
- `BOT_NAME`: 발신자 이름과 인사말에 사용할 이름. 기본값은 **회고냥**입니다.
- `MISSED_SUBMISSION_FINE`: 미제출 1회당 벌금. 기본값은 **10,000원**입니다.
- `DEADLINES`: 회차별 마감일. 일요일, 2주 간격으로 지정합니다.

명단만 바꿀 때는 예약 일정을 수정할 필요가 없습니다. 마감일을 바꿀 때는 워크플로의 UTC cron 날짜도 맞춰 주세요.

## 폴더 관리

`sync`, `run`, `status --send` 실행 시 명단에 맞춰 폴더를 관리합니다.

- 새 참여자의 폴더와 현재 회차 폴더를 만듭니다.
- 기존 회고 파일은 그대로 둡니다.
- 명단에서 빠진 사람의 폴더는 `[종료] 이름`으로 바꿉니다. 이름이 겹치면 `(2)`, `(3)`을 붙입니다.
- 다시 참여하면 기존 종료 폴더를 복원합니다. 충돌이 있으면 덮어쓰지 않고 중단합니다.
- 마감일 **00:00**에는 다음 회차 폴더도 만듭니다. 현재 회차에는 그날 23:59까지 제출할 수 있습니다.
- 마지막 회차가 끝나면 다음 회차 폴더를 만들지 않습니다.

빈 폴더를 Git에 보관하기 위한 `.gitkeep`은 제출로 인정하지 않습니다.
관리 기록이 없는 기존 폴더는 이름이 한글 2~10자이고 `YYYY-MM-DD` 하위 폴더가 있을 때만 참여자 폴더로 인식합니다.

## 알림

한 회차당 아래 다섯 번, 총 35번 알립니다.

- **D-3 · D-2 · D-1 00:00:** 남은 기간과 제출 현황
- **마감 당일 00:00:** 오늘 23:59 마감 안내
- **마감 다음 날 00:00:** 확정된 제출 결과와 다음 회차 안내. 마지막 회차에는 종료 인사를 보냅니다.

모든 알림에 현재 참여자 중 벌금이 있는 사람의 누적 금액과 횟수를 표시합니다. 전체 합계와 탈퇴자는 표시하지 않으며, 해당자가 없으면 벌금 부분을 생략합니다.
수동 실행은 날짜와 관계없이 현재 회차의 일반 현황을 보냅니다. 스터디 종료 후에는 마지막 회차 결과를 보냅니다.

GitHub Actions 예약 실행은 지연되거나 누락될 수 있어 자정 정각 도착을 보장하지 않습니다. 공개 저장소는 60일간 활동이 없으면 예약 실행이 비활성화될 수 있습니다. [GitHub 예약 실행 안내](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## 제출 판정과 마감 확정

`이름/회차마감일/` 아래에서 글이 있는 **`.md`, `.txt`, `.html`, `.pdf`** 파일을 찾습니다. 하위 폴더도 검사하며 하나 이상 인정되면 제출입니다.

- 공백·줄바꿈·보이지 않는 문자만 있는 파일은 인정하지 않습니다.
- 숨김 파일·폴더, 심볼릭 링크, 코드·이미지·압축 파일은 제외합니다.
- Markdown·텍스트·HTML은 UTF-8이어야 합니다. HTML은 주석·태그·스크립트·스타일 등을 제외한 본문 글을 확인합니다.
- PDF는 텍스트를 추출할 수 있어야 합니다. 손상·암호화·빈 PDF와 이미지만 있는 PDF는 제외합니다.

마감 이후 처음 실행될 때 **마감 시점의 참여자 명단과 제출 결과를 한 번만 확정**합니다. 예약 실행을 놓쳐도 다음 실행에서 누락된 회차를 함께 확정합니다.
현재 명단에 새로 들어온 사람에게 과거 회차 벌금을 부과하지 않습니다.

GitHub 저장소에서는 [저장소 활동 API](https://docs.github.com/en/rest/repos/repos#list-repository-activities)의 실제 반영 시각으로 마감 다음 날 **00:00 미만**의 `main` 상태를 찾습니다. 커밋을 미리 만들어도 마감 뒤에 푸시했다면 인정하지 않습니다. API나 해당 Git 기록을 확인할 수 없으면 임의로 판정하지 않고 중단합니다.
전체 Git 이력이 필요하며, 워크플로는 `fetch-depth: 0`과 `GITHUB_TOKEN`을 사용합니다. GitHub 원격이 없는 로컬 저장소에서만 커미터 시각을 사용합니다.

확정된 결과는 `.study/state.json`의 `rounds`에서 읽습니다. 이후 지난 날짜 폴더에 글을 추가·수정·삭제해도 제출 결과와 벌금은 바뀌지 않습니다. 과거 회차의 리마인드를 복구할 때도 확정 결과를 사용합니다.

## 벌금 집계

- 미제출마다 해당 회차에 기록된 벌금액을 합산합니다. 실제 입금 확인이나 납부 처리는 하지 않습니다.
- 개인별 누적 금액과 횟수는 현재 `MEMBERS`에 있는 사람 중 미제출 기록이 있는 사람만 표시합니다.
- 전체 합계는 표시하지 않습니다. 탈퇴자의 과거 기록은 보존하며, 다시 참여하면 기존 벌금도 개인별 누적 금액에 반영합니다.
- 마감 당시 `MISSED_SUBMISSION_FINE`을 회차별로 저장합니다. 나중에 설정을 바꿔도 과거 금액은 유지되며, 마감 처리가 늦게 실행돼도 마감 당시 설정을 사용합니다.
- 중도 포기 벌금 30,000원은 운영자가 별도로 관리하며 자동 집계에 포함하지 않습니다.

## 최소 운영 기록

`.study`에는 `state.json` 하나만 보관합니다. 별도 일정 파일은 만들지 않으며 전체 일정은 `schedule` 명령으로 확인합니다.

- `members`: 이름과 실제 폴더 이름. 탈퇴·복귀 시 기존 파일을 찾는 데 사용합니다.
- `rounds`: 회차별 제출 여부와 당시 1회 벌금액. 개인별 누적 금액과 횟수는 여기서 계산합니다.
- `events`: 예약 알림별 `pending` 또는 `sent` 상태.
- `manual`: 가장 최근 수동 실행 하나의 ID와 상태.
- `version`: 기록 형식 버전.

메시지 전문, Discord 메시지 ID, 확인 시각, 제출 결과의 중복 사본, 지난 수동 실행 목록은 저장하지 않습니다.
`run.lock`은 실행 중 충돌 방지용 로컬 파일이며 Git에 올리지 않습니다.

## GitHub Actions에서 실행하기

**Actions → Study automation → Run workflow**에서 모드를 선택합니다.

- **`send` (기본값):** 폴더와 마감 기록을 동기화하고 일반 현황을 보냅니다.
- **`preview`:** 일반 현황을 로그에서 확인합니다. 파일 저장과 전송은 없습니다.
- **`sync`:** 폴더와 마감 기록만 동기화합니다.
- **`replay`:** 놓친 예약 알림을 복구합니다. `event_id`에 `2026-10-04:final`처럼 지난 일정 ID를 입력합니다.

`event_id`는 `replay`에서만 사용합니다. 설정·스크립트를 `main`에 푸시하면 `sync`만 실행하며 알림은 보내지 않습니다.

## 로컬 명령

```sh
python3 -m pip install -r requirements.txt
python3 scripts/study.py schedule
python3 scripts/study.py status
python3 scripts/study.py preview
python3 scripts/study.py sync
```

`status`와 `preview`는 저장·전송 없이 미리 봅니다. `sync`는 폴더와 확정 결과를 저장합니다.
실제 전송 시에는 환경 변수 `DISCORD_WEBHOOK_URL`을 설정하고 아래 명령을 사용합니다.

```sh
python3 scripts/study.py status --send --persist
python3 scripts/study.py run --send --persist
python3 scripts/study.py run --send --persist --event 2026-10-04:final
```

`--persist`는 변경 사항을 커밋하고 `origin`에 푸시합니다. 미커밋 변경이 없는 최신 `main` 전용 체크아웃에서 실행합니다.
`--persist` 없이 전송하면 기록이 로컬에만 남으므로 운영에서는 함께 사용해 주세요.

## 재실행과 전송 실패

전송 전에 `pending`을 저장하고, Discord의 성공 응답을 확인한 뒤 `sent`로 바꿉니다.
이미 보낸 예약 알림과 가장 최근 수동 실행의 재시도는 다시 보내지 않습니다. 오래된 수동 작업을 `Re-run jobs`로 다시 실행하는 대신 **Run workflow**로 새 작업을 시작해 주세요.

응답 확인에 실패하면 `pending`을 남기고 중단합니다. 새 수동 실행도 이전 수동 `pending`을 먼저 확인해야 합니다.

1. 채널에서 실제 도착 여부를 확인합니다.
2. 도착했다면 해당 `events` 항목의 값을 `sent`로, 수동 실행이면 `manual.status`를 `sent`로 수정합니다.
3. 도착하지 않은 것이 확인되면 해당 `events` 항목 또는 `manual` 항목만 지우고 새로 실행합니다.
4. 수정한 상태 파일을 커밋·푸시합니다. `rounds`의 확정 결과는 지우지 않습니다.

네트워크 오류 때 도착 여부를 알 수 없는 경우가 있으므로 무조건 재전송하지 않습니다. 오류 내용은 Actions 로그에서 확인합니다.
동시 실행 제한을 사용하며, 실행 중 원격 `main`이 바뀌면 자동 병합하지 않고 중단합니다.
